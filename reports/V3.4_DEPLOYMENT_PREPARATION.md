## 6. UPSTASH REDIS CONFIGURATION SPECIFICATION

To support distributed document coordination, session revocation, and replay protection:

1. **Instance Type:** Standard / Serverless Redis.
2. **Region:** `ap-southeast-1` (Singapore) — Matches Neon compute location for lowest network latency.
3. **Transport Security:** TLS must be enabled (`rediss://` protocol, port `6379`). Both `src/lib/redis.ts` and `server/collab-server.ts` automatically configure `{ tls: {} }`.
4. **Key Patterns & TTLs Utilized:**
   - `collab:consumed_tickets:<ticket_id>`: Set with 300s (5-minute) TTL for atomic ticket replay defense.
   - `collab:events`: Pub/Sub channel for instantaneous document deletion, permission revocation, and restore events.
   - `collab:yjs:<doc_id>`: Pub/Sub channel for multi-instance cross-server Yjs sync updates.
   - `collab:lock:<doc_id>`: Distributed lock keys for database persistence debouncing.
   - `ratelimit:<key>`: Sliding window rate limit counters.

## 10. RECOMMENDED DEPLOYMENT EXECUTION ORDER

When ready to deploy, execute in the following sequence:

1. **Step 1 — Create Upstash Redis Database:**
   Create an Upstash Redis database in `ap-southeast-1` and copy the `rediss://` connection URL.
2. **Step 2 — Generate Shared Secret:**
   Generate a 256-bit token secret: `openssl rand -hex 32`.
3. **Step 3 — Deploy Render WebSocket Service (`collabspace-collab`):**
   - Connect Git repository to Render.
   - Configure Environment Variables (Section 5.2).
   - Verify build and confirm `GET https://<render-subdomain>.onrender.com/health` returns `{"status":"ok"}`.
4. **Step 4 — Deploy Vercel Next.js Application (`collabspace`):**
   - Connect Git repository to Vercel.
   - Set `NEXT_PUBLIC_COLLAB_WS_URL=wss://<render-subdomain>.onrender.com`.
   - Configure Environment Variables (Section 5.1).
   - Trigger production deployment.
5. **Step 5 — Post-Deployment Verification:**
   - Perform end-to-end multi-user editor sync, comments, and document persistence test.
